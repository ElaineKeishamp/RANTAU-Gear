# Project guidance

This is RANTAU Gear, a VB.NET Windows Forms application targeting .NET 10.

- Preserve Option Strict On and the IRentalRepository boundary.
- Apply the installed antislop core, UI, human, and copywriting skills for interface work. Read DESIGN.md for the project's design data. The current task uses DURING mode; resolve the mode normally in future sessions.
- Codebase Memory MCP is already connected. Use its project index when helpful, but inspect VB.NET source directly where symbol coverage is absent.
- Supabase integration is in progress. Read docs/BUSINESS_RULES.md and docs/SUPABASE_SETUP.md before changing online contracts. Primary login, online reads, and master-data editors use SupabaseRentalRepository through the async IRentalRepository members. DummyRepository and synchronous members remain for explicit test/demo previews only; Master writes use save_master_data with request UUID and optimistic row_version; Reservations and received DP use preview_reservation/reserve_with_dp through async repository methods. Pickup, rent balance and deposit are now connected through GetPickupDetailsAsync/PickupReservationAsync. Return/QC, admin approval and deposit settlement are connected through GetReturnDetailsAsync/ProcessReturnAsync. The QC response deliberately excludes customer identity and cash ledgers. Preserve action roles and full-unit inspections; never settle before admin approval or without confirming actual refund/receipt. Booking lifecycle changes use GetBookingChangeDetailsAsync/PreviewExtensionAsync/ChangeBookingAsync and RPC change_booking with confirmed old due/additional amount, request UUID and immutable retry payload. Expiry history is per selected reservation; effective expiry/capacity already uses server time without a background UI job. Use the selected bound RecordId, never a grid row index, for mutations. Confirm actual receipt and exact server quote; reuse the same request UUID/payload only for retry. Do not insert credentials, pretend the demo is online, or ship demo passwords as production authentication.
- DISTRIBUTION AUTHORIZATION: owner explicitly authorized publish on 2026-11-21. A self-contained Windows x64 folder and ZIP are authorized; no installer is requested. Pending manual checks in docs/PRE_DISTRIBUTION_REVIEW.md remain pending. Reports use read_report snapshots; staff Auth actions use server-side staff-admin with verify_jwt=true and verified Auth identity, never an admin key in desktop.
- User output location: save generated artifacts, exports, screenshots, backups, and configurable task temporary/cache files only under `D:\elaine\SEM 5\Pemrograman Visual-backup`. Do not write task outputs to drive C. Reading existing installed tools or skills on C is allowed. Keep edits to existing project source in this workspace. Request filesystem escalation if writing the output folder requires it; do not silently use a different location.
- Build: dotnet build RANTAUGear.slnx. Run the application to check layout and role-specific navigation.
